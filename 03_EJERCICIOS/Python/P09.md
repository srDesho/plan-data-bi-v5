## Situación

El ERP exporta precios como texto con formatos distintos («Bs 11,50», «11.5», «11»). Para sumar sin errores de redondeo conviene guardarlos como enteros en centavos.

## Qué recibe y qué devuelve

- **Recibe:** `texto`: el precio como str, con espacios opcionales, prefijo `Bs` opcional y coma o punto como separador decimal. Sin separador de miles.
- **Devuelve:** Un entero: el precio en centavos.

## Reglas

- Rechaza lanzando `ValueError` cuando el texto no es un número, es negativo, no es finito (`NaN`, `inf`) o tiene más de dos decimales.
- Nunca rellenes un precio ilegible con 0: cambiaría las ventas.
- El resultado debe ser exacto: `'2.05'` son 205 centavos.

## Ejemplos (para entender el formato; el corrector usa otros casos además de estos)

- `precio_centavos('Bs 3,75')` → `375`
- `precio_centavos('0.10')` → `10`
- `precio_centavos('12')` → `1200`
- `precio_centavos('Bs')` → lanza `ValueError`
- `precio_centavos('-0,5')` → lanza `ValueError`
- `precio_centavos('3.456')` → lanza `ValueError`
- `precio_centavos('')` → lanza `ValueError`

## Pistas (en este orden, solo cuando las necesites)

1. **Orientación.** Separa dos problemas: limpiar el texto (espacios, `Bs`, coma) y validar el número resultante.
2. **Concepto Python.** Reemplaza la coma por punto antes de convertir. Para convertir texto a número con control del error y sin aproximaciones usa `Decimal` del módulo `decimal`; `str.removeprefix` y `strip` limpian (capítulo 08).
3. **Si no cuadra.** Prueba `precio_centavos('2.05')`. Si obtienes 204, multiplicaste un `float` por 100: los decimales binarios son aproximaciones. Si una entrada inválida no lanza error, revisa qué excepción captura tu `try`.
